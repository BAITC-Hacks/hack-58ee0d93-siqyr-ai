# Данные, эталон и проверка качества

Исходные записи, протоколы, evaluate_stt.py и evaluation/ в эту ветку документации не включены. Указанные пути относятся к локальным материалам Alibi; подробное содержание спорных фрагментов остаётся в локальном review.

| `task_description/Совещание №2.mp3` | 206.03 с | 14 STT сегментов, DOCX с 6 поручениями | Корректность спорных сроков и деталей поручений |

Прочитаны оба DOCX и оба STT-транскрипта. Спорные звуковые фрагменты в рамках планирования не были подтверждены прослушиванием: ниже конкретное задание Alibi. Не выдавать замечания manual_review за окончательный ground truth.

WER 28.75% и 12.35% из старого сравнения нельзя показывать как достоверную точность: DOCX отличается от записи, числа записаны иначе. До аудио-эталона эти числа только диагностические. 16/16 означает обнаружимость поручений человеком в текстах, а 8/16 — качественную оценку восстанавливаемости основных полей; ни одно число не является результатом нового извлекателя.

## Проверка спорных фрагментов

Alibi слушает ниже, второй участник подтверждает спорное слово. Записываем дословно услышанное, источник и автора проверки. Когда разобрать невозможно — unresolved, без выбора «как в DOCX».

| Приоритет | Запись и секунды оригинала | Вопрос |
|---|---|---|
| 1 | №2: 30.19–60.47 и 179.83–206.03 | Какой срок окончательно согласован; относится ли поздняя фраза к тому же поручению? Проверять весь сегмент с 179.83 с, а не только фрагмент после 195 с. |
| 2 | №1: 45.68–60.27 и 90.30–120.23 | Какое местоположение относится к поручению? Не смешать его с другим местом из следующей темы. |
| 3 | №1: 179.59–209.38 | Полнота действия и окончательный срок после обсуждения нескольких вариантов. |
| 4 | №2: 164.21–206.03 | Не смешаны ли срок исполнения поручения и правило, описывающее последующую работу? |
| 5 | №1: 164.48–179.59, 209.38–224.06, 224.06–269.52; №2: 90.61–105.73 | Отсутствующие детали действий: их нет в аудио или они потеряны STT? |

Результат будущей проверки: `evaluation/audio_adjudication.md` с записью, start/end, heard_text, protocol_text, verdict, reviewer. `evaluation/ground_truth.json` хранит canonical поручения, ссылки, owner, raw deadline, normalized deadline/null и resolution. Оба файла пока предстоит создать. Исходные DOCX сохраняются без правки. Фактическая дата старых встреч неизвестна; текущая дата файла/хакатона не является датой встречи.

## Эталон без утечки

1. Ground truth строится по аудио, DOCX — вспомогательный список кандидатов. Отмечаем исключённые/добавленные задачи и изменение знаменателя, а не подгоняем всегда к 16.
2. Экстрактор получает только STT, сведения о встрече и подтверждённый список участников. Никогда не передавать expected assignments/таблицы DOCX/ручной эталон как подсказку.
3. Автоматический результат сохраняется до правок. Reviewed — отдельный snapshot. Показываем число человеческих исправлений, время review и полноту после него.
4. Новый case для проверки не использовать в few-shot/prompts до замера. Два старых файла — development/regression, не независимый репрезентативный benchmark.

## KK и mixed собственная запись

До 14:30 записать 60–90 секунд тремя людьми с явным согласием, используя вымышленные имена из seed. Сохранить `data/samples/team_mixed_01.wav`, consent/manifest отдельно. Участники могут зачитывать `data/seed/demo_meeting.json`, но реальная разметка времени делается заново по записи; заранее заданные 56.4 с не копировать.

Нужны 3 акустически разных голоса, короткая самоидентификация каждого и 4 поручения из seed. В записи должны присутствовать: RU реплика; цельная KK реплика про передачу данных; mixed реплика с переключением языка внутри предложения; конкретная дата и «жұмаға дейін». Дата сценария явно 2026-09-23. Проверить казахский текст носителем перед записью. Добавить отдельную 15–20-секундную фразу без поручений как отрицательный контроль.

Для испытания изменения срока отдельно записать вымышленное «до пятницы → согласовано до понедельника» и поручение человеку, который не говорит. Это labels-first сценарии команды; не вставлять туда тексты старых встреч. Эталон фиксируется после проверки произнесённого. Не требуем актёрской идеальности и не называем результат доказательством качества в шумных реальных совещаниях.

## OpenAI API, синтез и Brev

Разрешённый командой первый этап: API создаёт вымышленные диалоги с нуля. До 12 текстовых случаев: ru/kk/mixed × явный срок/отсутствующий срок/смена срока/внешний исполнитель. Поручения и ожидаемые поля заданы заранее; 3 случая с отрицательным результатом можно включить вместо повторов. 8 dev, 4 holdout, отдельная audio evaluation. Несколько языков в 12 случаях — smoke, не статистическое доказательство.

Manifest: `synthetic=true`, `origin=generated|scripted|recorded_script`, model ID, prompt version, created_at, seed, language, intended labels, human reviewer, split, audio_path/null. Запись реальных голосов команды на выдуманном сценарии называется «сценарий синтетический, голоса команды», а не синтезированное аудио.

В OpenAI/Brev запрещены исходные файлы, STT-тексты, таблицы протоколов, имена/данные из них и их перефразирования. Используем доверенный synthetic manifest, а не клиентский флаг. Не отправлять содержимое meetings в Codex для нового генератора/отладки; кодовые задания используют выдуманные fixtures. Ключи только в локальном env. Никаких API-вызовов в рамках этого планирования не выполнялось.

## Метрики и командные пороги

| Метрика | Как считать | Цель для MVP, не результат |
|---|---|---|
| Recall поручений | Корректно найденные gold-задачи / все подтверждённые audio gold-задачи; один-к-одному сопоставление | ≥85%; если gold остаётся 16, минимум 14/16 |
| Precision поручений | Подтверждённые gold задачи / все выданные задачи; дубли и выдуманные отдельно | ≥90%; показать числитель/знаменатель |
| Owner accuracy | Правильные исполнители / все gold-задачи; пропуск считается ошибкой; отдельно conditional на найденных | ≥85% raw; reviewed — все спорные случаи разобраны |
| Deadline accuracy | Верный смысл срока (включая корректный null/событие/конфликт) / все gold-задачи | ≥85% raw; ошибочная конкретная дата при неизвестном сроке — ошибка |
| Полнота действия | Есть ключевые объекты/охват, не только общий глагол | Ручной checklist по gold, raw и reviewed отдельно |
| Привязка к источнику | Все выданные поручения имеют существующий аудиосегмент и совпадающую цитату | 100% технически валидных ссылок; это не равно 100% истинности |
| Риск | Непомеченные неверные имена/места/сроки; известные конфликты, не попавшие в review | 0 непомеченных критических ошибок на проверенных случаях |
| Диаризация | 10–20 вручную размеченных смен голоса: совпадение после оптимального сопоставления speaker labels | Показать k/n по RU и новой записи; DER только если размечены все интервалы, иначе не называть это DER |
| KK/mixed | Поля 4 поручений собственного сценария по языковым evidence-фрагментам | 4/4 после review, raw публикуется как есть; отдельно KK и mixed, даже если n мало |
| Время | model loading, normalize, diarize, STT, LLM, export, review, total wall time | Короткий warm demo ≤120 с; это целевой бюджет, не обещание |
| Воспроизводимость | Два запуска тем же manifest на ноутбуке; offline run | Сходятся поля/режимы; фактическое время фиксируется |

При holdout ниже порога не скрываем ошибку и не учим prompt на нём до отчёта. Исправление потом — новый run/version. Если автоматическое качество недостаточно, позиционирование — «черновик с обязательной проверкой», не «надёжное автопротоколирование».

Отчёт Alibi: `evaluation/results_final.md`, таблица на каждую запись и режим, аппаратная конфигурация, versions/hashes, количество правок и пять худших ошибок с time spans. Формат top-5: факт аудио → STT → extractor → влияние → обнаружен ли review → исправление. Для старых двух записей сначала подтвердить происхождение/право публичного показа; при неопределённости демонстрируем только собственный сценарий.
