# RAG-чат по встречам

## Архитектура

```text
React / IndexedDB ── /api/chat/* ──► FastAPI (auth, индекс, история, цитаты)
                                      │
                                      └── Unix socket ──► private AI service
                                                        BGE-M3 embeddings
                                                        BGE reranker v2 M3
                                                        local LLM via llm.py
```

Фронтенд никогда не обращается к AI-сервису напрямую. Публичный API принимает текст встреч и поручений из браузерного хранилища, сохраняет версии фрагментов в SQLite и индексирует доступные серверные `Run`. Внутренний сервис доступен только через `RAG_AI_SOCKET`; `scripts/run_local.sh --with-rag` запускает его через `uvicorn --uds` с приватными правами файла. На рабочем профиле `LLM_PROVIDER=local`, а `LLM_BASE_URL` должен указывать на loopback этого же сервера. Ни API, ни AI-сервис не скачивают модели во время запроса.

## Подготовка

1. Задать в `.env` `LLM_PROVIDER=local`, `LLM_BASE_URL=http://127.0.0.1:11434/v1` и модель `MODEL_MAIN`, уже загруженную в локальный Ollama или vLLM. Реальные тексты встреч нельзя отправлять через SSH-туннель на Brev: адрес `localhost` в этом случае не означает локальную обработку.
2. Однократно выполнить `bash scripts/setup.sh --with-rag --download-rag-models`. Модели: [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3) для dense embeddings (1024 измерения) и [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) для cross-encoder rerank. Весовые файлы лежат в игнорируемом Git каталоге `models/rag/`; скрипт записывает их commit SHA в `rag-model.json`.
3. Запустить `bash scripts/run_local.sh --offline --with-rag`. `GET /api/health` возвращает `rag.service`, `rag.models_present` и `rag.llm_local`. Эти поля подтверждают конфигурацию, но не заменяют реальный запрос к модели.

На Mac с небольшим запасом диска веса и PyTorch могут быть тяжёлыми. `RAG_DEVICE=cpu` — умолчание; на машине с CUDA задать `RAG_DEVICE=cuda`. При отсутствии весов API отвечает 503, не подменяя embedding поиском по ключевым словам.

## Контракт

- `POST /api/chat/sync` принимает `{meetings: [{id,title,status,date,summary,transcript:[{id,speaker,text}],tasks:[{title,assignee,deadline_text,status}]}]}`. Индекс пользователя обновляется только при изменении текста/модели. Отсутствующие браузерные встречи удаляются из его индекса. Аудио и `Blob` не передаются.
- `POST /api/chat/conversations` создаёт пустую сессию `{title}`. `GET /api/chat/conversations` перечисляет свои сессии. `GET /api/chat/conversations/{id}` отдаёт сообщения. `PATCH .../{id}` меняет название, `DELETE .../{id}` удаляет сессию и сообщения.
- `POST /api/chat/messages` принимает `{question,conversation_id}` и возвращает `{conversation_id,message:{id,role,text,sources}}`. При первой отправке без ID может создать сессию; UI обычно создаёт её заранее.
- У каждого источника есть название встречи, фрагмент, тип (`browser` или `run`), ID, индекс реплики, время начала при наличии и статус. Фронт показывает эти данные рядом с ответом. Для браузерной встречи ссылка открывает её карточку.

Индекс использует dense similarity и пересечение слов для отбора кандидатов, затем cross-encoder rerank и максимум шесть фрагментов для LLM. В ответе допускаются только номера извлечённых источников; отсутствие или выдуманный номер превращает ответ в сообщение о невозможности подтверждения. Это проверка ссылок, а не доказательство истинности каждого утверждения: пользователь сверяет ответ с фрагментами.

## Приватность и Brev

Пока организаторы не подтвердили допустимый контур, Brev используется только для полностью вымышленных тестовых встреч. Локальные записи, текст, embeddings, индекс и чаты не загружаются туда. При `AUTH_MODE=disabled` API работает как общая демонстрационная учётная запись; для разграничения личных чатов нужен `AUTH_MODE=local|keycloak|hybrid`. Браузерный клиент перед синхронизацией требует локальный `VITE_API_URL` (`localhost`, `127.0.0.1` или `::1`).

## Проверка

`python -m pytest tests/test_rag_chat.py` проверяет контракт с детерминированным тестовым AI-адаптером, версии индекса, историю сессий, удаление и отсутствие прямого `/internal` маршрута на публичном API. Для проверки реального качества и задержки нужен отдельный smoke с загруженными моделями и локальной LLM; тестовый адаптер этого не доказывает.
