# ТЗ: Система автопротоколирования совещаний с фиксацией поручений

Источник: HackAlem_AI_Система_автопротоколирования_совещаний_с_фиксацией.docx (от организаторов).

## Проблема и ценность
Протоколы совещаний фиксируются вручную секретарями, что занимает много времени и создаёт риск потери или искажения поручений, сроков и ответственных лиц. Как следствие — снижается контроль исполнительской дисциплины. Автоматизация протоколирования освободит время секретарей и повысит прозрачность контроля за исполнением поручений.

## Пользователь и сценарий
**Сценарий 1.** Секретарь совещания включает запись → участников уведомляют, что ведётся запись и транскрибация с помощью ИИ → система фиксирует реплики, распознаёт поручения (кто, что, к какому сроку) → по итогам совещания формируется саммари → управленческие сотрудники используют саммари для отслеживания хода работы и контроля сроков.

**Сценарий 2.** Руководитель/куратор поручения получает автоматическое напоминание при приближении срока исполнения или при его просрочке.

## Техническая задача
Разработать прототип ИИ-ассистента (например: бот/веб-интерфейс + backend + модуль распознавания речи), который:
- распознаёт речь участников (speech-to-text) на русском, казахском и «шала-казахском» (смешанной речи);
- различает говорящих (диаризация) и привязывает поручения к конкретному участнику;
- выделяет из транскрипта поручения с указанием ответственного лица и срока;
- формирует итоговое саммари совещания.

## Вход и выход
**Вход:** возможность подключаться в качестве участника Teams, Zoom, Google Meet, аудио/видеозапись совещания (или live-поток).
**Выход:** текстовый протокол/транскрипт + структурированный список поручений (ответственный, срок, суть) + краткое саммари; экспорт итогового протокола в файл (PDF/DOCX).

## Данные и доступ
Участники сами предоставляют тестовую аудиозапись совещания (реальную или смоделированную) на русском/казахском/смешанном языке. Использование синтетических/смоделированных записей допускается. При использовании реальных записей данные должны быть анонимизированы для демонстрации.

## Обязательный минимум
- Распознавание речи участников.
- Понимание русского языка.
- Понимание казахского языка.
- Понимание шала-казахского (смешанной речи).
- Автоматическое выделение поручений с ответственным и сроком.
- Различение говорящих (диаризация) с привязкой поручения к конкретному человеку.
- Экспорт итогового протокола в файл (PDF/DOCX).

## Дополнительно
- интеграция с системами электронного документооборота (СЭД);
- дашборд со статусами поручений (в работе / просрочено / выполнено);
- автоматическая рассылка выдержки из протокола ответственным лицам;
- классификация поручений по срочности/направлению;
- голосовая идентификация участников по тембру;
- возможность развёртывания проекта в закрытом контуре заказчика (on-premise).

## Ограничения
- Решение должно допускать размещение в закрытом контуре заказчика; передача аудио/текста во внешние облачные API запрещена — участникам следует использовать локальные/self-hosted модели распознавания речи.
- Работа с чувствительной информацией — приватность и защита данных обязательны.
- Полноценная интеграция с СЭД и промышленное развёртывание — вне обязательной части.
