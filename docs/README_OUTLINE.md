# Структура README и проверка воспроизводимости

В исходной рубрике трека это 25/100. По новой рубрике помогает качеству, масштабу и ответам жюри. README пишет Meiirlan параллельно коду, финальную инструкцию проверяет другой участник.

## Секции в финальном README

1. **Что работает сейчас.** Пользователь, проблема, один пример; ссылка на локальный запуск и видео. Список реализованных функций и ограничений, без TODO и обещаний будущих функций как готовых.
2. **Демонстрация за 3 минуты.** Два режима — real и явно обозначенный replay. Входной файл, дата сценария, ожидаемые поля, где услышать источник и получить файлы.
3. **Системные требования.** Фактическая ОС/CPU/GPU/RAM/диск демо-машины, версии Python/Node/FFmpeg/Ollama; измеренный peak memory и время. Минимум без GPU только после проверки, не по размеру весов.
4. **Подготовка и лицензии.** Сначала сеть для пакетов/весов; ссылки и gated условия pyannote; hashes, размеры, model IDs; STT создана до хакатона. Токены не в команде, истории shell, screenshots или git.
5. **Установка одной командой.** `bash scripts/setup.sh --profile laptop --download-models` после перечисленных системных prerequisites. Команда должна существовать и быть проверена. Если ещё не реализована — честные ручные шаги вместо фиктивной кнопки.
6. **Запуск одной командой.** `bash scripts/run_local.sh --profile laptop --offline`; адреса localhost:5173 и 127.0.0.1:8000. Graceful shutdown, health, что делать без модели/при занятом порте.
7. **Настройка.** Таблица env: provider, base URL, model IDs, model dirs, data dir, modes, font, upload limit. Secret-free `.env.example`; real при пустом endpoint не работает, никакого silent OpenAI fallback.
8. **OpenAI сначала, local потом.** Только доверенные synthetic fixtures в dev_openai; идентичный контракт; как переключить, как доказано отсутствие external calls. Общий бюджет не выдумывать: $50 на ключ, $50 Brev.
9. **Архитектура и контракты.** Небольшая схема и ссылки на CONTRACT/STACK. Реальные стадии, не декоративный список «агентов». Сохраняемый raw, draft, approved snapshot, источник, версии.
10. **Проверка результата.** `pytest`, frontend build, e2e script; таблица фактических raw/reviewed метрик по RU/KK/mixed, n и ссылки на источники данных. Old WER с caveat или убрать из главного экрана.
11. **Offline и данные.** Работа без сети после подготовки; отключённый tracing/telemetry и локальные assets; расположение runtime файлов и удаление через удаление собственного run-dir. Это smoke-доказательство прототипа, не сертификация безопасности.
12. **Ограничения.** Неизвестные даты старых встреч, маленькая выборка, шум/overlap, имена, ручное подтверждение, нет meeting bots/СЭД/полной промышленной защиты; статус напоминаний явно.
13. **Воспроизводимость и состав сдачи.** commit SHA, dependency locks, model manifest, synthetic demo manifest, seed/replay, видео, команды/путь данных; авторы и вклад за хакатон.

## Абзац для вставки в README

Рабочий сценарий Siqyr AI обрабатывает аудио, транскрипты и протоколы на ноутбуке с локальными моделями. Разработку и проверку структуры поручений мы начинаем с OpenAI API на полностью вымышленных тестовых встречах, затем переключаем тот же контракт на локальную LLM; записи заказчика и любые производные от них в API не передаются. Codex используется для разработки. OpenAI-совместимый endpoint и запуск открытых весов gpt-oss сами по себе не означают обращение к hosted OpenAI API, поэтому достаточность выбранного использования API для правил хакатона подтверждается отдельно у организаторов. Brev уже настроен и используется для GPU-экспериментов на синтетике; передачу туда данных встреч не включаем без подтверждения соответствия требованиям закрытого контура. После загрузки зависимостей и весов основной демо-сценарий рассчитан на работу без интернета; фактический offline-тест и его ограничения указываем рядом с результатами.

Этот абзац описывает выбранный режим. Перед публикацией заменить «рассчитан» на «проверен» только после успешного теста и добавить фактическую дату/машину. Не писать, что согласие организаторов уже получено.

## Приёмка README

- Другой участник выполняет инструкции в новом env/data_dir, не пользуясь частными ADM путями.
- Все ссылки/команды/скрипты существуют, gated условия объяснены до скачивания.
- Нет внешних шрифтов или runtime model pulls при отключённой сети.
- Real, mock и replay отличаются в интерфейсе и в сохранённом результате.
- Новая реальная короткая запись обрабатывается, а не подменяется ожидаемыми assignments.
- После правки/approve DOCX и PDF совпадают с UI, кириллица и казахский текст читаемы.
- `LLM_BASE_URL` на произвольный внешний хост и пустой URL в local отвергаются.
- Нет секретов, `.env`, runtime БД, неразрешённых записей или весов в staged diff.
- Успех/неуспех проверки внесён в STATUS с временем; ограничения остаются в README.
