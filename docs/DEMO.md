# Демо на три минуты

Исходные записи, протоколы, evaluate_stt.py и evaluation/ в эту ветку документации не включены. Указанные пути относятся к локальным материалам Alibi; подробное содержание спорных фрагментов остаётся в локальном review.

## Главное обещание

«Siqyr AI превращает двуязычную встречу в проверяемые поручения. Секретарь слышит источник спорного поля, подтверждает решение и получает согласованный протокол. Обработка встречи остаётся на ноутбуке».

## Точные входы

1. **Основной новый live input:** `data/samples/team_mixed_01.wav`, 60–90 с, собственная запись по DATA.md; 3 голоса, 4 поручения, дата сценария 2026-09-23. Этот файл пока нужно записать. Если full warm processing >120 с, сделать отдельный clip по фактически измеренным границам двух законченных реплик RU/KK; указать offset в manifest, не брать выдуманные timestamps seed.
2. **Заранее обработанный реальный прогон:** `task_description/Совещание №2.mp3`, 206.03 с. Сравнение спорных сроков: 30.19–60.47 и 179.83–206.03. Использовать публично только после проверки происхождения/анонимизации и прослушивания; финальный срок до этого неизвестен.
3. **Резервный понятный источник:** `task_description/Совещание №1.mp3`, 75.41–90.30 (кандидат для проверки основных полей поручения). Другой кандидат для проверки: 179.59–209.38 (содержание поручения и срок). Те же условия публичного показа.
4. Если исходники показывать нельзя, используем только собственный mixed файл и отдельный записанный пример смены срока. `data/seed/demo_meeting.json` — только mock-разработка, не live STT evidence.

Не склеивать вырезки из разных мест в «новую непрерывную встречу» без обозначения. Все ссылки UI ведут к секундам оригинала.

## Подготовка до выхода

- Два прогона без сети после загрузки весов; loopback UI/API, звук и зарядка проверены.
- Вкладки: старт, сохранённый real review, PDF/DOCX, 5 слайдов. Все материалы на диске.
- До 16:15 записать run ID **реального** результата в `docs/STATUS.md`; REPLAY_RUN_ID назначить ему. Не придумывать ID в плане.
- Replay помечен «ранее выполненный реальный прогон», показывает исходное время выполнения; mock — «тестовые данные». Видеозапись подписана датой и режимом.
- Если реальный run падает: сказать «покажем сохранённый прогон той же версии», перейти к нему, сохранить ошибку. Не выдавать replay за live.
- Если auto-диаризация или local extraction не готовы: сказать это прямо. Ручная разметка не заменяет доказательство обязательной автоматической функции.

## Пять слайдов

1. Секретарь тратит время на перенос поручений; риск — неверные имя/срок. Без выдуманных рыночных цифр.
2. Пользовательский путь и показ проверки по аудио.
3. Локальная архитектура; собственная STT, отдельно роль OpenAI API в synthetic/dev.
4. Таблица raw/reviewed, язык, n и худшие ошибки; измеренное время.
5. Пилот и развитие: 20 встреч одной организации, сравнение времени ручной подготовки/проверки, цель пилота согласовать; очереди, СЭД и напоминания позже.

## Ответы жюри

- **Почему не обычный транскрибатор?** В демонстрации есть связывание поручения с источником, ответственный/срок, проверка и согласованный экспорт; объясняем только реализованные отличия.
- **Какова точность?** Показываем фактические raw/reviewed на маленьком наборе; пока нет обобщения на шум, разные акценты и пересекающуюся речь.
- **Где OpenAI?** Codex при разработке и hosted API на отдельно созданных synthetic тестах; runtime встречи local. Зачёт именно этого использования подтверждается правилами организаторов, не заявляем его заранее.
- **Разве Brev — локально?** Это удалённый self-hosted ресурс, не автоматически закрытый контур; в основном демо данные остаются на ноутбуке.
- **Кто такой SPEAKER_01?** Акустическая метка; имя подтверждает человек. Автоматическая голосовая идентификация личности не заявлена.
- **Что при неверном/отсутствующем сроке?** Сохраняем дословный текст и null/флаг конфликта, возвращаем к аудио, не сочиняем дату.
- **Что сделали за хакатон?** STT существовала раньше; показать новые интеграцию, извлечение, review и экспорт по git history и actual функциональности.
- **Как масштабировать?** После пилота — workers с ограничением памяти, durable очередь, tenant storage/RBAC, аудит, СЭД. Это roadmap, не реализованные свойства.
