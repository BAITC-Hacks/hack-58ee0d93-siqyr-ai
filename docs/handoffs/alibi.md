# Передача AI-модулей от Alibi

Ветка `codex/ai-implementation` основана на `origin/main` `b6be3804c5df5030ed54ec6a9c8c1976dff6cb59`. Это файл передачи для интеграции; сообщение само по себе никому не отправляет уведомление.

## Готово

- `backend/stt/engine.py:transcribe(Path, lang) -> list[Segment]` использует локальную mixed RU/KK TorchScript-модель. Копия весов из ADM находится в `models/stt/`; SHA-256 указан в манифесте. Бинарные файлы исключены из Git.
- `backend/stt/diarize.py` использует локальную Community-1. HF-токен и доступ к gated модели проверены; веса скопированы в `models/diarization/`, манифест зафиксирован, бинарные файлы исключены из Git. При отсутствии модели остаётся явная метка `UNKNOWN`, при перекрытии `OVERLAP`.
- `backend/agents/runner.py:propose/execute` даёт одно структурированное предложение с одной попыткой исправления и сверяет цитаты/индексы с raw-транскриптом. Несколько неверных цитат сообщаются вместе. Неподтверждённое цитатой имя понижается до `Не указан`; после утверждения `execute()` работает без LLM.
- `backend/app/llm.py` сохраняет async-интерфейс и на `api.openai.com` выполняет синхронный OpenAI SDK в отдельном потоке. Это устранило локальные таймауты `AsyncOpenAI` на этом Mac; продуктовый smoke и итоговая eval-серия использовали именно `llm.complete`. Для иных endpoint остаётся прежний async-клиент.
- `backend/app/pipeline.py:guard_llm_destination` допускает в real-режиме только loopback endpoint; OpenAI API доступен через API лишь для встроенного серверного demo без загруженного файла. Произвольный внешний адрес и загруженная запись блокируются. Прямая одноразовая оценка двух разрешённых пользователем mock-записей выполнялась вне API guard.
- Пользователь выбрал OpenAI `gpt-6-luna` и отложил локальную LLM. `MODEL_MAIN`/`MODEL_FAST` теперь указывают Luna в конфигурации и `.env.example`; endpoint задаётся явно. Ключи не скопированы в checkout и не сохранены в Git.

## Проверка

- `.venv/bin/python eval/check.py guard`: **25/25** проверок парсера, источников, ошибок ответа, смены/конфликта срока, неутверждённой предложенной даты и неизвестного исполнителя.
- Продуктовый Luna-клиент на 12 полностью вымышленных RU/KK/mixed случаях: **12/12 валидных Proposal, 9/9 найденных ожидаемых поручений по source overlap, 0 лишних**; 3 отрицательных случая пустые. Точная словарная проверка действия — 7/9, включая одно реально слишком краткое действие и одно смысловое перефразирование. 13 API-вызовов, оценка $0.002565. Подробности: `eval/results_luna_product.md`, сырые ответы v6 и `_scores.json`. Hosted eval теперь сверяет фиксированный SHA-256 `inputs.json` до вызова API. Старые Qwen-замеры — исторический baseline; локальную LLM по просьбе пользователя больше не развивали.
- Две записи из `task_description` пользователь подтвердил как смоделированные тестовые данные и разрешил проверку Luna. **Аудио обрабатывалось локально; Luna получила только STT-текст.** Запись №1: 274 с, 39 сегментов, 4 голосовые метки плюс `OVERLAP`; Luna дала 10 поручений за 2 вызова, соответствующих 10 пунктам приложенного протокола. У 6 исполнитель подтверждён корректно, у 3 — `Не указан`, одно имя и название области искажены STT. Часть действий во второй половине менее подробна, чем в письменном протоколе: STT теряет объект аудита и детали согласования бюджета.
- Запись №2: 206 с, 45 сегментов, 5 голосовых меток плюс `OVERLAP`; Luna дала 7 поручений за 1 вызов: все 6 основных пунктов письменного протокола покрыты, обучение и смета представлены отдельными действиями. Имя юриста распознано неверно; у 6 поручений исполнитель `Не указан`. В финальной речи сроки отличаются от письменного протокола, поэтому протокол годится для ориентировочной ручной сверки, но не для точного WER или жёсткой оценки каждого срока.
- Интеграционный smoke с авторизованным mock backend и реальным Luna runner прошёл создание → approval → DOCX/PDF (`200`), 4 поручения. Ранее локальный 20-секундный real STT/Community-1/Ollama smoke прошёл тот же API-путь. Полный API-путь с обеими длинными записями и Luna не запускался; их оценка шла через продуктовые STT и runner напрямую.
- Проверка перед интеграцией: `.venv/bin/python -m pytest -q -p no:cacheprovider` — **36 passed**. Локальный API `/api/health` вернул `200`; `scripts/demo_e2e.sh` прошёл в live mock и replay режимах: 10 сегментов, 4 поручения, утверждение, DOCX и PDF. Оба файла скачаны и проверены; `pdftotext` сохранил русские и казахские символы. PDF теперь автоматически находит Unicode-шрифт macOS, а скрипт проверяет оба формата.

## Ограничения и запросы интеграции

1. `Segment.speaker`: схема v0.1 требует строку. Для неизвестного голоса и наложения сейчас используются `UNKNOWN`/`OVERLAP`. Нужны nullable speaker и `review_reasons`, иначе UI может принять их за установленные голоса.
2. `RunInput.meeting_date`: upload без проверенной даты заполняет её текущим днём. Нужны `meeting_date: date | None` и `meeting_date_verified`; пока runner не выводит ISO-даты из относительных или безгодовых сроков. Все сроки из двух записей оставлены текстом, `deadline=null`.
3. `AssignmentDraft.assignee/evidence/review_reasons`: схема v0.1 требует имя строкой и не сохраняет цитаты/причины проверки. Нужны nullable assignee, сохранённые evidence, review reasons/status и `confidence=null` до калибровки. Пока `Не указан` блокирует отправку выдержки неизвестному исполнителю. Сервер должен повторно сверять индексы и цитаты с raw-сегментами перед утверждением.
4. Если понадобится удалённый self-hosted endpoint, отдельным решением расширить текущий строгий loopback allowlist. Для новых загруженных встреч внешний API закрыт. Текущая прямая оценка двух разрешённых mock-записей не является общим разрешением на передачу новых встреч.
5. Границы говорящих остаются главным узким местом. На записи №1 четыре акустические метки при пяти людях в протоколе, во второй половине несколько быстрых смен говорящих слиты. На записи №2 число меток совпало, но короткие реплики и имена местами слиты. Нужна проверяемая привязка голосовой метки к человеку; подстановка имени только по соседству без цитаты рискованна.
6. На этом Mac `.venv` использует Python 3.11.11 с установленными Torch/pyannote, тогда как `pyproject.toml` требует ≥3.12. Для другого хоста нужна воспроизводимая ML-среда. Прежние блокировки mock pytest из-за импорта `scripts.demo_e2e` и отсутствия PDF-шрифта устранены.
7. Проверка всех абсолютных дат в одном длинном STT-сегменте может отклонить два независимых поручения с разными сроками; нужен отдельный безопасный разбор такой реплики. Не считать это покрытым текущими 12 синтетическими случаями.
8. Браузерный AI demo пока не проверен: `frontend/src/hooks/useWorkspace.ts` работает с локальным Dexie/IndexedDB и не вызывает backend API. Подключение UI к pipeline находится в зоне фронтенда; для полной демонстрации нужен этот адаптер и повторная проверка в браузере.

## Безопасность и файлы

Исходные `.mp3`, `.docx`, STT-расшифровки и ответы Luna по этим двум записям не добавлены в Git; временные результаты лежат только в `/private/tmp`. Секреты остаются в исходном `.env`, который не копировали. В `models/` коммитятся только манифесты и небольшие конфигурационные файлы, не веса. Локальный Ollama, запущенный для исторических измерений, остановлен.
