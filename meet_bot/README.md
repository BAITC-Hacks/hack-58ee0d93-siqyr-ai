# Siqyr AI: бот для питча Google Meet

Бот входит в тестовую встречу как обычный участник с отдельным **личным Google-аккаунтом**. Google Workspace организации для такого показа не нужен. Организатор вручную впускает бота. Бот выключает микрофон и камеру, пишет в чат уведомление о записи, сохраняет удалённые аудиотреки по кускам и после выхода оставляет локальную сессию. Пароли и коды бот не вводит.

## Быстрый показ на ноутбуке

Из корня этой ветки (Python 3.11–3.12, установленный Chrome/Chromium от Playwright):

```powershell
python -m pip install -r meet_bot/requirements.txt
python -m playwright install chromium
python -m meet_bot login
python -m meet_bot join --url https://meet.google.com/abc-defg-hij --title "Демо Siqyr"
```

1. `login` открывает окно. Человек входит в специально созданный тестовый Google-аккаунт, затем нажимает Enter в терминале. Профиль с cookies остаётся только в `BOT_PROFILE_DIR`.
2. Организатор создаёт встречу со своего обычного аккаунта, бот входит по ссылке. Если появится запрос на допуск, организатор принимает его. Все участники заранее согласны с записью.
3. Два человека произносят короткий **вымышленный** сценарий на русском и казахском. В чате видно уведомление бота. После встречи оператор нажимает Ctrl+C в CLI (бот дописывает последний кусок) либо вызывает HTTP `DELETE /bots/{id}` для сервисного режима.
4. В `OUTPUT_DIR/<session_id>/` находятся `segment-*/chunk-*.webm`, `timeline.jsonl`, `finish.json`. Для текущего backend импортируйте файл командой ниже и откройте полученный `run_id` в Siqyr. На экране показывайте реальные стадии обработки, review и утверждённый экспорт.

```powershell
python -m meet_bot import-run --session-id SESSION_ID --title "Демо Siqyr"
```

Пока `/api/sessions` ещё не реализован, `join` пишет в `FileSink`. `import-run` использует **существующий в main** `POST /api/runs` с файлом WebM. При нескольких сегментах нужен `ffmpeg` в PATH. Backend должен быть запущен на `127.0.0.1:8000` и иметь готовые локальные STT/LLM для real-run. Таймлайн остаётся рядом с локальной записью: текущий API его ещё не принимает.

## Управляющий API

```powershell
python -m meet_bot serve
```

`POST http://127.0.0.1:8100/bots` с JSON `{"meet_url":"https://meet.google.com/abc-defg-hij","title":"Демо"}` возвращает `bot_id` и локальный `session_id`. `GET /bots/{id}` показывает статус, число записанных кусков и событий говорящих. `DELETE /bots/{id}` просит бота выйти и закрыть файл. Пока один профиль Google разделяется всеми вызовами, одновременно запускается только один бот, даже при большем `MAX_BOTS`.

Настройки: `API_BASE_URL`, `BOT_API_TOKEN`, `BOT_PROFILE_DIR`, `OUTPUT_DIR`, `CHUNK_SECONDS`, `ADMISSION_TIMEOUT_S`, `ALONE_TIMEOUT_S`, `MAX_DURATION_S`, `MAX_BOTS`. Для демо API доступен только на loopback. `BOT_API_TOKEN` нужен, если авторизация Siqyr включена. Папки с профилем, записями и HTML/скриншотами ошибок игнорируются Git.

## Что проверено и что нужно проверить на встрече

Локальные unit-тесты проверяют сегменты, повтор того же seq, диск при ошибке HTTP и условия завершения. `tests/fixtures/loopback.html` создаёт два WebRTC-пира в одной вкладке и 3-секундный тестовый звук; `test_loopback.py` проверяет непустые куски и длительность через `ffprobe`, когда Playwright/Chromium/ffprobe установлены.

Селекторы Google Meet и разметка субтитров могут меняться. Данные говорящих записываются **только если интерфейс отдал явное имя рядом с субтитром**; `speaker_events: 0` означает, что эта часть не подтверждена. События входа и выхода при доступном счётчике участников имеют `name: null`. Если счётчик скрыт, автоматический выход по одиночеству не срабатывает: используйте `DELETE`. Не обещайте точность ±2 секунды или полную запись до теста с двумя участниками. При ошибке страница и скриншот сохраняются в `debug/`; они могут содержать личные данные и не должны попадать в репозиторий.

Если Google требует проверку аккаунта или блокирует вход через автоматизированный браузер, проходите её вручную в `login` либо показывайте существующий браузерный режим записи Siqyr. Бот не обходит CAPTCHA, 2FA или политику доступа. Не выдавайте локальный loopback за реальную встречу.

## Развёртывание и запасной захват

`Dockerfile` запускает headed Chromium под Xvfb, с отдельным томом `/data` для профиля и записи. Первый интерактивный вход удобнее сделать на ноутбуке; переносить профиль с cookies на чужой сервер без разрешения нельзя. Бот не пишет звук системного микрофона.

Если перехват удалённых `RTCPeerConnection`-треков в данной версии Meet не даёт звук, запасной путь для изолированного Linux-контейнера: PulseAudio null sink как системный output Chromium, `ffmpeg -f pulse -i <monitor>` в сегменты WebM/Opus. Этот путь описан для диагностики и пока **не реализован/не проверен**. Не подменяйте им успешный результат JS-перехвата без проверки звука.
