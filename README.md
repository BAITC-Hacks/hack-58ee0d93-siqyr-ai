# Siqyr AI — автопротоколирование совещаний

> Запись совещания на русском, казахском или шала-казахском → расшифровка с говорящими → поручения (кто, что, к какому сроку) с цитатой-доказательством → проверка и утверждение секретарём → протокол DOCX/PDF, реестр поручений, напоминания о сроках. Распознавание речи работает на своём сервере, в закрытом контуре.

Кейс HackAlem AI: [docs/TASK.md](docs/TASK.md) · Критерии: [docs/CRITERIA.md](docs/CRITERIA.md) · API: [docs/CONTRACT.md](docs/CONTRACT.md) · Ход работы: [docs/STATUS.md](docs/STATUS.md)

## Проблема и пользователь

Секретарь ведёт протокол вручную: это долго, а поручения, сроки и ответственные теряются или искажаются. Руководителю потом не на что опереться, чтобы проверять исполнение.

Siqyr AI делает черновик протокола за секретаря, но не решает за него. У каждого поручения есть цитата и таймкод исходной реплики. Секретарь щёлкает по спорному сроку, слушает эти секунды записи и подтверждает или исправляет. Итоговые файлы и реестр строятся только из утверждённой редакции. Руководитель или куратор получает напоминание, когда срок подходит или уже прошёл.

Заказчик кейса — Самрук-Казына: закрытый контур, корпоративный вход через Keycloak, задачи ведутся в Jira. Под это сделаны локальные модели, режимы авторизации и интеграция с Jira.

В UI карточка встречи показывает серверный черновик: саммари, решения, говорящих, поручения с цитатой и таймкодом, причины проверки; секретарь правит, подтверждает или исключает поручения и утверждает |

## Как это работает

```text
 Загрузка файла │ Запись с микрофона (WebM-чанки) │ Бот Google Meet
                          │
                          ▼
 FastAPI: очередь, 1 worker ──── SSE: этапы обработки в реальном времени
                          │
                          ▼
 FFmpeg → VAD (ONNX) → STT wav2vec2-CTC (TorchScript, CPU) → диаризация pyannote
                          │   raw-транскрипт: реплики с таймкодами, не изменяется
                          ▼
 propose(): один структурированный вызов LLM (+1 попытка исправления JSON)
   → саммари, решения, поручения, у каждого поля цитата и индекс реплики
   → grounding: цитаты сверяются с raw, сроки — с датой совещания
   → review_reasons: owner_uncertain, deadline_conflict, scope_incomplete, overlap …
                          │
                          ▼
 Секретарь: слушает источник, правит (revision), подтверждает говорящих, утверждает
                          │   неизменяемый approved snapshot
                          ▼
 execute() без LLM → реестр поручений, DOCX/PDF, напоминания, задачи Jira по кнопке
```

Статусы запуска: `recording → queued → transcribing → running → awaiting_approval → executing → done`, а также `rejected` и `error`.

Принципы, заложенные в код:

- **Модель предлагает, человек утверждает.** После утверждения LLM больше не вызывается: реестр, файлы и напоминания строятся детерминированно из снимка.
- **Каждое поле проверяемо.** Цитата должна дословно найтись в исходной реплике, иначе ответ модели отклоняется ([backend/agents/grounding.py](backend/agents/grounding.py)). Raw-текст не редактируется, правка человека хранится отдельно (`corrected_text`).
- **Неизвестное остаётся неизвестным.** Исполнитель и срок могут быть `null`. Относительный срок без подтверждённой даты совещания не превращается в дату. При конфликте сроков сохраняются оба кандидата ([backend/agents/deadlines.py](backend/agents/deadlines.py)).
- **Спорное блокирует утверждение.** Конфликт срока, отсутствие источника, неподтверждённый говорящий и неполное действие требуют явного решения секретаря.
- **Режим виден.** Каждый результат помечен `source_mode = real | mock | replay`, mock не выдаётся за реальную обработку.

«Агентов» здесь не несколько ради числа: извлечение — один структурированный вызов с проверкой, остальное детерминированный код. Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/STACK.md](docs/STACK.md), [docs/DECISIONS.md](docs/DECISIONS.md).

## Быстрый старт (ноутбук, без Docker)

Нужно заранее: Python 3.12+, Node.js 22.18+, Git Bash на Windows. Для реальной обработки ещё FFmpeg и [Ollama](https://ollama.com). Сеть нужна только на время установки.

```bash
bash scripts/setup.sh                      # .venv, зависимости по lock, .env из .env.example, npm ci, preflight
```

Если lock не ставится на вашей платформе, повторите с `--no-lock`.

По умолчанию `.env` включает mock STT и mock-агентов: пайплайн проходит на синтетическом совещании без моделей. Фронтенд работает только со входом, поэтому в `.env` задайте:

```ini
AUTH_MODE=local
JWT_SECRET=<случайная строка от 32 символов>
BOOTSTRAP_ADMIN_USER=admin
BOOTSTRAP_ADMIN_PASSWORD=<пароль от 12 символов>
```

Администратор создаётся при первом запуске, после этого удалите bootstrap-пароль из `.env`. Учётки на каждую роль (`test.admin`, `test.secretary`, `test.viewer` и др.) создаёт `python scripts/seed_test_users.py`, он же печатает общий пароль. Подробнее: [docs/AUTH.md](docs/AUTH.md).

```bash
bash scripts/run_local.sh --offline        # API 127.0.0.1:8000 + фронтенд 127.0.0.1:5174, ничего не скачивает
bash scripts/demo_e2e.sh                   # сквозная проверка через API: запуск → правка → утверждение → DOCX + PDF
```

Откройте http://127.0.0.1:5174. `run_local.sh` сначала запускает `scripts/preflight.py` и проверяет, что порты свободны. `--api-only` поднимает только API, `--port` меняет порт. Остановка — Ctrl+C.

На Windows вместо `.venv/bin/...` используйте `.venv/Scripts/...`.

### Реальная обработка на локальных моделях

Один раз, с сетью:

```bash
bash scripts/setup.sh --with-stt           # torch CPU, onnxruntime, pyannote.audio, CLI hf
.venv/bin/hf auth login                    # токен HF не хранится в git; заранее примите условия pyannote на huggingface.co
```

Перед скачиванием весов впишите в `.env` локальные модели: `MODEL_MAIN=qwen3:4b`, `MODEL_FAST=qwen3:1.7b`. Скрипт делает `ollama pull` именно для этих имён.

```bash
bash scripts/setup.sh --download-models    # ollama pull, веса STT и диаризации в models/, manifest с SHA-256
```

Затем в `.env`: `STT_MODE=real`, `AGENT_MODE=real`, `LLM_PROVIDER=local`, `LLM_BASE_URL=http://127.0.0.1:11434/v1`. Запустите `ollama serve` и `bash scripts/run_local.sh --offline`. Своя запись через API:

```bash
bash scripts/demo_e2e.sh --file запись.wav --meeting-date 2026-09-23 --mode real
```

Если модели или LLM недоступны, API отвечает 503 и называет причину, ничего не скачивая. `--offline` дополнительно запрещает LLM не на loopback.

### Docker

```bash
cp .env.example .env

```

API — http://localhost:8000/api/health, фронтенд — http://localhost:5173. Основной проверенный путь — локальный запуск без Docker.

## Модели и лицензии

| Компонент | Модель | Где работает |
|---|---|---|
| STT | [alibiserikbay/kazakh-russian-mixed-stt](https://huggingface.co/alibiserikbay/kazakh-russian-mixed-stt) (Apache-2.0): wav2vec2 + CTC, казахский, русский и смешанная речь за один проход, жадное декодирование, 16 кГц. Обучена участником команды до хакатона | CPU, локально |
| VAD | `vad.onnx` из того же репозитория | CPU, onnxruntime |
| Диаризация | [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) — gated: нужно принять условия на Hugging Face | CPU, локально |
| LLM, рабочий профиль | Ollama: `qwen3:4b`, резерв `qwen3:1.7b` | loopback |
| LLM, разработка | `gpt-6-luna` через OpenAI API — только на полностью вымышленных стенограммах | внешний API |

Размеры и SHA-256 весов — в [models/stt/manifest.json](models/stt/manifest.json) и [models/diarization/manifest.json](models/diarization/manifest.json). Сами веса в git не попадают. Веса STT занимают около 756 МБ.

## Закрытый контур и приватность

- Аудио обрабатывается только локально: FFmpeg, VAD, STT и диаризация работают на CPU сервера.
- В real-режиме LLM разрешена только на loopback или на явно перечисленном внутреннем хосте ([backend/app/pipeline.py](backend/app/pipeline.py)). Внешний адрес и пустой URL останавливают обработку. Молча переключиться на облачную модель код не может.
- OpenAI API допускается только для встроенного синтетического демо без загруженного файла: сервер сам ставит признак синтетики и не доверяет его клиенту.
- `run_local.sh` отключает телеметрию Hugging Face и pyannote и tracing Agents SDK. `--offline` запрещает сетевые обращения библиотек. Шрифты и ресурсы UI локальные.
- Все данные запуска лежат в `DATA_DIR`. Аудио отдаётся только пользователям департамента, которому принадлежит совещание.
- Внешние интеграции выключены по умолчанию. Jira Cloud, Gmail и Resend выносят текст поручений наружу, поэтому для них — только сценарные записи. В контуре заказчика — Jira Data Center и внутренний SMTP-relay.
- Бот пишет в чат встречи, что идёт запись и транскрибация ИИ. В UI перед записью секретарь отмечает, что участники об этом уведомлены.

Физический прогон с отключённой сетью пока не проводился. Mock-путь внешних вызовов не делает, real-путь после загрузки весов рассчитан на работу без сети. Это прототип, не сертифицированное решение по защите данных.

**Аудио.** Две смоделированные записи кейса обработаны локальными STT и диаризацией, затем извлечение по тексту:

- запись №1, 274 с: 39 реплик, 4 голоса + наложения; 10 поручений соответствуют 10 пунктам письменного протокола. У 6 исполнитель верный, у 3 — «не указан», одно имя STT исказил;
- запись №2, 206 с: 45 реплик, 5 голосов + наложения; 7 поручений покрывают все 6 пунктов протокола, у 6 исполнитель «не указан».

WER не считали: письменный протокол не совпадает дословно с речью, старые цифры 28.75% и 12.35% диагностические ([docs/DATA.md](docs/DATA.md)). Время обработки и пиковую память пока не измеряли.

## Ограничения

- Браузерная проверка UI (загрузка → черновик → правка → утверждение → DOCX/PDF → реестр) выполнена на mock STT/агентах; с реальными моделями через UI не прогонялась. Карточки встреч без серверной обработки по-прежнему хранятся только в браузере.
- Real-путь проверен по частям: STT и извлечение — на двух записях напрямую, через API — 20-секундным прогоном. Полный прогон длинной записи через API и UI ещё не сделан.
- Диаризация сливает быстрые смены говорящих: на записи №1 четыре голоса при пяти людях. Имена и связь голоса с человеком подтверждает секретарь; биометрической идентификации нет.
- Локальная LLM `qwen3:4b` заметно слабее `gpt-6-luna` на том же наборе. Качество зависит от выбранной модели и железа.
- Относительные сроки без подтверждённой даты совещания остаются текстом. Уверенность модели (`confidence`) не калибрована и всегда `null`.
- Бот Meet зависит от разметки Google Meet и требует ручного входа тестового аккаунта. Бота для Teams и Zoom нет.
- Нет интеграции с СЭД. Выдержки ответственным формируются, но по почте не рассылаются — письма уходят только как напоминания о сроках.
- Одна очередь и один worker: прототип для одного ноутбука или сервера, не промышленное развёртывание.

## Структура

```text
backend/app       API: FastAPI + SQLModel + SQLite, SSE, review, экспорт, авторизация, напоминания, Jira
backend/stt       распознавание речи, VAD и диаризация
backend/agents    propose()/execute(), grounding цитат, разбор сроков, промпты, mock-раннер
backend/shared    общий контракт (Pydantic-схемы)
frontend          веб-интерфейс: React 19 + TypeScript + Vite + Mantine + Dexie
meet_bot          бот для Google Meet: Playwright, запись удалённых аудиотреков
scripts           setup, run_local, preflight, demo_e2e, seed_test_users
eval              синтетические наборы, эталоны, сырые ответы моделей и отчёты
tests             pytest для API, авторизации, контракта, почты, Jira
models            manifest весов (сами веса не в git)
data              синтетические демо-данные; runtime/ создаётся при запуске
infra             Dockerfile фронтенда, nginx, заметки по деплою
docs              задача, контракт, архитектура, решения, статус
```
