# Независимая оценка gpt-6-luna через синхронный транспорт

Дата: 2026-09-23. **Только 12 полностью вымышленных текстовых fixtures:** 8 dev, затем 4 holdout без правки промпта/runner между наборами. Ожидаемые ответы хранятся отдельно в `expected.json` и читаются после сохранения всех сырых ответов набора. Prompt SHA-256 записан в обоих raw-файлах; первый Qwen baseline и прежние частичные сетевые логи не перезаписывались. Аудио, реальные протоколы и их производные не использовались.

Команды из корня checkout:

```bash
.venv/bin/python eval/check.py hosted_sync --split dev --output eval/luna_sync_dev_v1.json
.venv/bin/python eval/check.py hosted_sync --split holdout --output eval/luna_sync_holdout_v1.json
```

Этот путь вызывает `runner.propose`, но **транспорт в eval только для измерения**: синхронный `requests.post` к OpenAI Chat Completions. Это **не продуктовый** `backend.app.llm.complete`. Ключ считывается из исходного `.env` только в память. Запросы содержали только проверенные synthetic fixtures, `model=gpt-6-luna`, `max_completion_tokens=1024`, `reasoning_effort=none`, продуктовую JSON Schema, не более двух попыток на случай. Кеш не применялся. Dev: 10 HTTP-вызовов, оценка стоимости $0.001658; holdout: 4 вызова, $0.000671; всего **14 вызовов, $0.002329**, значительно ниже лимита $5.

## Транспортный вывод

Ранее `AsyncOpenAI`/`httpx2.AsyncClient` на этом Mac давали `ConnectTimeout`/`APIConnectionError`; сырые частичные события сохранены в `luna_dev_v2.json`. **Это не общая недоступность сети или OpenAI API:** синхронные GET и Chat POST получили HTTP 200, и все 14 вызовов этой серии завершились ответом. Синхронный eval-путь доказывает доступность модели для синтетических запросов, но не исправляет продуктовый асинхронный клиент. Для продуктового использования нужен отдельный транспортный fix и новый smoke через `backend.app.llm.complete`.
