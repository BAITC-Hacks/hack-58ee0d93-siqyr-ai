# Независимая синтетическая проверка извлечения

`inputs.json` содержит только полностью вымышленные стенограммы: 8 dev и 4 holdout. `expected.json` хранит эталон отдельно. Входы написаны после фиксации меток; реальные записи, STT-тексты, протоколы, имена и их пересказы не использовались. Все имена, отделы и совещания выдуманы. Аудио здесь нет.

Навык `synthetic-data` применён к проектированию матрицы ru/kk/mixed, числа поручений и формулировок сроков. Генератор через MODEL_FAST не использовался: работа ограничена `eval/`, внешние API для этого задания не вызываются. Текст 12 случаев прочитан агентом; человеческая проверка казахских формулировок остаётся открытой.

## Запуск

Из корня рабочего checkout:

```bash
.venv/bin/python eval/check.py guard
.venv/bin/python eval/check.py local --split dev --model qwen3:4b
.venv/bin/python eval/check.py local --split holdout --model qwen3:4b
.venv/bin/python eval/check.py hosted --split dev --output eval/luna_dev_v2.json
.venv/bin/python eval/check.py hosted --split holdout --output eval/luna_holdout_v2.json
.venv/bin/python eval/check.py hosted_sync --split dev --output eval/luna_sync_dev_v1.json
.venv/bin/python eval/check.py hosted_sync --split holdout --output eval/luna_sync_holdout_v1.json
```

`guard` использует искусственные ответы LLM в памяти, проверяет `runner.propose` и `runner.execute` без сети. `local` обращается только к явно проверенному loopback HTTP endpoint (по умолчанию `http://127.0.0.1:11434/v1`); он использует нативный Ollama `/api/chat` с `format=json`, `think=false`, `num_predict=1024`. Модель задаётся аргументом. Никакого fallback на облако нет. До вызовов модели читается только `inputs.json`; `expected.json` открывается уже после сохранения всех сырых предложений соответствующего split. Файлы `local_*.json` содержат сырые предложения и шаги, `local_*_scores.json` — сравнение. Holdout нельзя использовать для настройки промпта до его первого замера; после любого изменения промпта нужен новый идентификатор запуска и отдельный отчёт.

`hosted` разрешён только для этих проверенных вымышленных fixtures. Он читает `OPENAI_API_KEY` из исходного `.env` только в память, настраивает существующий `backend.app.llm.complete` на `gpt-6-luna` через отдельный `Settings` и отключает кеш. Запрос ограничен `max_completion_tokens=1024`, `reasoning_effort=none`, максимум двумя попытками на случай и бюджетом серии $5. Ключ, `.env`, реальные записи и эталонные ответы не записываются в результат и не отправляются модели. Цена для оценки стоимости: $0.10 за миллион input и $0.50 за миллион output токенов, согласно [официальной странице модели](https://developers.openai.com/api/docs/models/gpt-6-luna).

`hosted_sync` использует отдельный **только eval** синхронный `requests.post` к тому же Chat Completions endpoint и те же ограничения. Это исторический независимый замер при ошибках асинхронного клиента на данном Mac; он не проверяет продуктовый `llm.complete`. После исправления транспорта итоговая серия `hosted` через продуктовый клиент описана в `results_luna_product.md`.

## Что измеряется

Для каждого поручения: найдено ли оно по пересечению индексов источника, ключевые слова действия, исполнитель, дата, текст срока и точный набор исходных сегментов. Лишние поручения считаются false positives. Совпадение слов `task_terms` — грубая автоматическая проверка, не экспертная оценка полного смысла. Результат с ошибкой модели сохраняется как ошибка, а не как пустой успешный протокол. Guard отдельно проверяет пустой/битый/обрезанный JSON, отказ, неверные источники, отсутствие цитаты, повтор индекса и один repair.

Текущая схема v0.1 не имеет `assignee=null`, `evidence`, `review_reasons` и `confidence` в сохранённом `AssignmentDraft`. Для неизвестного исполнителя runner подставляет строку `Не указан`. Gold отмечает `null`; scorer считает этот sentinel семантически неизвестным и отдельно помечает его. При конфликте сроков можно проверить `deadline=null`, но сам признак конфликта в результате не сохраняется. Guard показывает, что синтаксически верная цитата может подтверждать обсуждение без поручения; семантическую ошибку ловит только независимый gold.
