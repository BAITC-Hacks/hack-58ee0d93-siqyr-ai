# Frontend: вход и доступ к страницам

## Границы

Экран входа, жизненный цикл сессии, guards и правила видимости навигации реализованы отдельно от транспорта. `AuthGateway` — внутренний интерфейс приложения. `ApiAuthGateway` использует `POST /api/auth/login` и `GET /api/auth/me`, а JWT хранит в `sessionStorage` вкладки. При отсутствии `VITE_API_URL` действует `UnconfiguredAuthGateway` без входа. Keycloak и ЭЦП требуют отдельных браузерных адаптеров и пока недоступны в UI.

Frontend guard ограничивает интерфейс. Сервер должен независимо проверять доступ к каждому ресурсу и операции. Изоляция IndexedDB не является шифрованием и не защищает данные от владельца браузерного профиля. Основание: [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).

## Слои

```text
app/composition/createAuthController
  → AuthGateway implementation
  → AuthController
  → AuthProvider / useAuth
  → GuestRoute / SecurityRoute
  → AuthenticatedWorkspace → QueryClient / WorkspaceProvider / Shell
```

- `modules/auth/domain`: сессия, пользовательские claims, проверка policy, безопасный локальный return path. Без React и HTTP.
- `modules/auth/application`: порт `AuthGateway` и `AuthController`. Контроллер отменяет устаревшие операции; поздний результат входа не может восстановить уже закрытую сессию.
- `modules/auth/infrastructure`: `ApiAuthGateway` для локального пароля; `UnconfiguredAuthGateway` никогда не создаёт сессию и используется без адреса API.
- `modules/auth/presentation`: контекст, форма, валидация, состояния ожидания/ошибки/истечения сеанса. Сырые сообщения транспорта не попадают в интерфейс.
- `app/routing`: применение policy к маршрутам и выбор первой доступной страницы.

## Состояния и маршруты

`checking` скрывает защищённое содержимое до результата восстановления. Ошибка восстановления остаётся отдельным состоянием с повторной попыткой. `anonymous` перенаправляется на `/login?returnTo=...`. Подтверждённая сессия пропускается только после проверки policy. Истёкшая сессия отзывается таймером; после возврата к вкладке время проверяется повторно.

`GuestRoute` перенаправляет вошедшего пользователя с login на сохранённый локальный путь. Внешние адреса, `//host`, обратные слеши, опасные закодированные значения и циклический возврат на login отклоняются.

При отказе в доступе отображается отдельный экран; рабочие компоненты и провайдер данных не монтируются. При выходе кеш очищается, запросы отменяются, запись освобождается. Выход во время записи требует подтверждения.

## Роли и разрешения

Единый реестр — `src/app/routing/access.ts`. Сейчас все существующие страницы требуют подтверждённую сессию. Конкретная матрица ролей не назначена заранее.

Пример будущей конфигурации после согласования значений claims:

```ts
settings: {
  rolesAnyOf: ['workspace-admin'],
  permissionsAllOf: ['workspace:settings:write'],
}
```

Семантика: хотя бы одна роль **и** все перечисленные разрешения. Пустой объект означает «любой вошедший пользователь». Явно пустой список требований запрещает доступ. Неправильная структура policy и отсутствие метаданных у защищённой страницы не открывают доступ. Не существует неявного обхода проверок по строке `admin`.

Та же policy используется для route handle и меню. Ограничения родителя и потомка объединяются через AND. Роли департамента нельзя автоматически превращать в глобальные роли: адаптер должен сохранять область действия согласно согласованной модели сервера. Сокрытие кнопок и клиентские проверки не заменяют серверную авторизацию изменений.

## Изоляция рабочего пространства

Рабочее пространство загружается лениво после разрешения guard. У каждого вошедшего пользователя собственный QueryClient и отдельная локальная база `siqyrai-workspace:<encoded principal id>`. При смене пользователя scope размонтируется и создаётся заново. Старая база `hackalem-workspace` не удаляется и не присваивается первому вошедшему пользователю автоматически; перенос прежних черновиков должен быть отдельным явным действием.

## Дизайн

Верстка воспроизводит согласованную композицию: фон с плоскостями документов, центральная форма и два альтернативных способа входа. Фон реализован CSS, интерфейс остаётся настоящими контролами Mantine. Цвета берутся только из существующих глобальных переменных: `--app-bg`, `--paper`, `--ink`, `--muted`, `--line`, `--accent`, `--accent-strong`, `--accent-soft`. Глобальная тема не дублируется в login-модуле.

## Проверки

`npm run check` проверяет границы архитектуры, TypeScript, тесты и production build. `tests/auth.test.ts` покрывает claims, роли/права, безопасный return path, гонки операций, ошибки и истечение сеанса. `tests/api-auth.test.ts` проверяет вход, восстановление JWT, отказ 401 и выход. Браузерный тестовый стенд с внедряемым адаптером находится в игнорируемом `.frontend-workbench/qa/auth/`; он не импортируется приложением и не входит в сборку.
